# 估值分析 SOP

判断一只股票"贵不贵"不能只看单一指标或绝对股价，必须多维交叉、并结合同行与自身历史。规划子问题时，尽量覆盖下列检查项，每项都应带上大写股票代码（ticker）。

## 分析清单（检查项）

1. **市盈率 P/E**：同时看 TTM（滚动）与 forward（前瞻）市盈率——盈利拐点时两者会明显背离。
2. **PEG**：市盈率 ÷ 盈利增速。P/E 高但增速更快时 PEG 可能仍然合理，避免只看 P/E 就下"贵"的结论。
3. **市净率 P/B**：重资产/金融股尤其关键，成长股参考意义较弱。
4. **市销率 P/S**：尚未稳定盈利的成长股用 P/S 替代 P/E。
5. **EV/EBITDA**：剔除资本结构与折旧差异，跨公司可比性优于 P/E。
6. **股息率**：收息型/价值型标的必看，与国债收益率对比。
7. **历史估值分位**：当前 P/E 处于自身近 3–5 年的高位还是低位分位。
8. **同行业横向估值对比**：与 2–3 家可比公司的 P/E、P/S 对比，判断是行业整体贵还是个股偏贵（可触发 industry_comparison SOP）。

## 规划提示

- 实时估值倍数（P/E、P/B、P/S、股息率、市值）→ 用 finance_query，子问题写成 "TICKER valuation / P/E / fundamentals" 形式。
- 历史估值分位、行业估值区间、分析师目标价 → 可用 rag_search 或 web_search 补充。
- 至少要产出覆盖"市盈率"和"同行/历史对比"两类的子问题，不能只查一个当前股价就下估值结论。

## 输出结构建议

先给结论（相对高估 / 合理 / 低估），再用上述指标逐条支撑，并明确指出所依据的对比基准（同行 or 自身历史）。
